# Testing Guide — Version 1.0.0

Version 1 testing has two distinct layers: automated artifact/semantic validation and Power BI Desktop usability validation.

## 1. Prerequisites

- Power BI Desktop
- PowerShell 7+
- .NET SDK
- Tabular Editor 2.28 for manual measure workflow validation

## 2. Data validation

Run:

```powershell
.\build\validate.ps1
```

Confirm required CSV files, columns, and schema pass.

## 3. Measure validation

The source contract is `scripts/metadata/MeasureDefinitions.json`.

Generate the TE2.28 script:

```powershell
.\scripts\tools\GenerateMetadata.ps1
```

Manual check:

1. Open the semantic model in Tabular Editor 2.28.
2. Run `scripts/GenerateMeasures.csx`.
3. Confirm measures are created on `Fact_Pipeline_SampleData`.
4. Check expressions, folders, formats, and annotations.

Automated builds do not depend on Tabular Editor. They materialize the authoritative measure set and verify its count against `MeasureDefinitions.json`.

## 4. Build validation

Run:

```powershell
.\build\build.ps1
```

The build verifies:

- authoritative template exists;
- expected fact table exists;
- measure count matches `MeasureDefinitions.json`;
- `_Measures.tmdl` is not generated by the template-first output;
- `Dim_Category[CategoryName] -> Fact_Pipeline_SampleData[Category]` exists;
- two expected expressions exist, including portable `DataFolder`;
- PBIR definition uses the expected schema/version and dataset path;
- exactly 28 `visual.json` files exist;
- every visual JSON parses successfully;
- visual JSON files do not contain UTF-8 BOMs;
- the exact artifact that will be published passes the visual gate.

## 5. Power BI Desktop UAT

Open:

```text
pbip/Pipeline_SLA_Tracker.pbip
```

Verify:

### KPI hierarchy

- KPI cards and visual field bindings display the expected measures.
- Measures resolve to `Fact_Pipeline_SampleData`.
- No broken field/measure references appear.

### Slicer behavior

- Category/environment/time filters are visible where configured.
- Changing a slicer visibly changes the expected visuals.
- Filter context does not break KPI calculations.

### Page and visual rendering

- Home renders correctly.
- Executive Overview renders correctly.
- SLA Exceptions renders correctly.
- Floating-bar/SLA visuals render with expected values.

### Resources

- Registered report images/resources display correctly.
- No missing image placeholders appear.

These Desktop checks cannot be proven solely by JSON parsing or semantic CI checks.

## 6. Release gate

A Version 1 release is accepted only when:

```text
Validation                  PASS
Measure contract            PASS
Semantic model              PASS
PBIR                        PASS
28/28 visual JSON           PASS
Published-artifact gate     PASS
Power BI Desktop smoke test PASS
```

## 7. Troubleshooting

### DataFolder points to a CI path

Check the generated semantic model and ensure `DataFolder` is resolved from the PBIP artifact context. Never commit a machine-specific absolute path.

### Measures are missing

Regenerate `scripts/GenerateMeasures.csx` from `scripts/metadata/MeasureDefinitions.json`, run it in TE2.28 for manual validation, and rerun the automated build.

### Visual count is not 28

Do not validate a separate generated tree. Regenerate from the authoritative template and rerun the build so the exact published artifact is gated.

### Visual JSON parse failure

Inspect the named `visual.json` for malformed JSON or BOM content. The build intentionally fails on malformed visual metadata.

### Desktop opens but visuals do not behave correctly

Treat this as a Desktop UAT issue, not as proof that CI is wrong. Verify field bindings, slicer interactions, registered resources, and the published artifact in Power BI Desktop.
